## What

Three fixes from last night's production incident (first post-cutover run announced ~50 historical digests into the group topic until Telegram returned 429; two runs failed; remediated manually in the prod DB).

1. **Freshness window** — `_TELEGRAM_MAX_AGE = 12h`: a digest older than 4 windows is marked `telegram_sent` directly (INFO log) instead of announced. A TL;DR notification is a real-time ping; any backlog shape (column-add migration defaulting old rows to 0 — the exact trigger here — restored backup, re-enabled channel, long outage queue) must never flood the topic. Site/email deliberately NOT windowed: the site is an archive and its backfill in the same incident was correct and desirable.
2. **Per-run 429 circuit breaker** — `TelegramSendError` gains a structured `status`; the first 429 flips a `_deliver`-scoped flag (threaded, no globals) and all remaining Telegram sends this run are skipped with one WARNING, retrying next run. Skips still count as failure so the OnFailure alert fires.
3. **`_plain_text` emphasis stripping** — live find on the site index: `**$100B ARR by year end**` rendered verbatim in an excerpt. `**`/`__` removed by string replace; `*pair*` by regex; single underscores untouched so `@user_name` survives.
