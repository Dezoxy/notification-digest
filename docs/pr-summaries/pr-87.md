## 3. Structure that was never written down

The README now states the four run modes, their cadences, and what each one consumes:

| Mode | Cadence | Input |
|---|---|---|
| window | every 6h | raw items |
| daily | 20:30 Budapest | that day's window digests |
| weekly | Sun 21:45 Budapest | the week's daily briefs |

Each rung consumes the one below — the daily never sees raw items, the weekly never sees anything but daily briefs. That's arguably the most load-bearing fact about this system and it appeared in no doc.

## Two notes that earned explicit callouts

Both are places the docs actively misled:

- **`TRANSLATE_TIMEOUT_SECONDS` applies per leg.** A safeguards refusal retries on the fallback model at the same timeout, so the worst case is 2× the configured value. Reading it as a single budget is exactly what left the window and daily systemd ceilings at zero margin (homelab #754 / #755).
- **The app refuses to start with every delivery channel disabled.**

Weekly cadence reflects homelab #755, which moved it to 21:45 Budapest.
