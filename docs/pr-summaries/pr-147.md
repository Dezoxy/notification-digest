## Description
Neither this repo nor the homelab repo documented how to replace the X cookie jar, so the 2026-09-06 expiry was recovered by reconstruction. This writes down what that took.

## The two details worth having in writing

Both are silent failure modes rather than things you'd discover by reading the code:

- **`auth_token` is HttpOnly**, so `document.cookie` in the Console returns only `ct0`. A jar built that way looks plausible and fails with `InvalidSession`. The Application panel reads the cookie store below that boundary.
- **Logging out of the source browser session invalidates the cookies**, so the export belongs in a dedicated profile that's then closed *without* logging out. `host_vars/01-myapps-vm/vars.yml` already recorded this — it just wasn't anywhere the person doing the refresh would look.

## Contents

Symptom → dedicated session → DevTools export → Key Vault (via file, so the credential never enters shell history) → deploy → confirm via the next digest's `source_counts`.

Plus a short closing note on why the other three session credentials need none of these mechanics: `REDDIT_SESSION_COOKIE` / `PATREON_SESSION_COOKIE` / `TG_SESSION` are env vars sent as hand-built headers over stateless `urllib`, or an MTProto auth key — nothing rotates, and there's no live jar to reconcile. Each already reports its own auth death explicitly.
