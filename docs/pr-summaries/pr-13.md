# PR #13: Replace the list format with a prose briefing
[View PR](https://github.com/Dezoxy/notification-digest/pull/13) · @Dezoxy · merged 2026-07-30 · `1fdc0f9` · `digest-quality-v2 -> main` · +492/-499 across 6 files

## Description
Reworked in place: this branch is now the **briefing format**, not the topic-grouped list it started as. Driven by real production output — the owner receives 50–100 items per window and found the list format still required reading everything.

## Why the list didn't work, and why a newsletter didn't either

Two prototypes were built against the **real 50 items** from delivered digest #3:

1. A single-narrative newsletter read beautifully but was dishonest — with an ASI group debating tokenomics next to a missile strike next to a Zcash upgrade, it manufactured through-lines that don't exist.
2. The list (this branch's original content) grouped by topic but still handed over an index to read.

## What shipped instead

The material is **three structurally different kinds**, and the prompt now handles each differently:

| Kind | Treatment |
|---|---|
| **Events** (news channels) | Clustered by story, merged across every source into one account |
| **Conversations** (group discussions, 30-char chatter threads) | Characterized — what was discussed, whether it concluded — never transcribed message-by-message. Allowed to say "nothing of substance" when that's true |
| **Chatter** (greetings, emoji, reactions, promo) | Counted only, never written about |

Plus: independent weighted sections ordered by importance, **explicitly forbidden from inventing connections between them** (most windows have no through-line); a ~900-word soft target; an ~8-section budget with minor items collapsing into one `## Also this window` prose paragraph rather than each claiming a heading; a `**TL;DR:**` opener that keeps its highlighted box; `## Needs attention` only when something genuinely needs action.

Citations are superscript-digit markdown links immediately after each claim, and every URL must be a collected item's URL **verbatim** — enforced by the existing `enforce_link_allowlist` and the HTML-level anchor-provenance pass, unchanged.

## Validation is deliberately thinner

`validate_output` now raises only when there is **zero real `## ` heading** — enough to reject a bare refusal, which is all a gate genuinely needs to catch. The three-specific-headings, exactly-once and ordering requirements are gone.

This is the lesson from the collector-failure-banner episode, cited in the docstrings: hard-gating stylistic compliance meant one stubborn model deviation cost an entire 3-hour digest cycle. Format expectations now live in the prompt and **warn rather than block** (missing TL;DR, zero citations). The fence-aware (backtick *and* tilde, matching-delimiter, opening-length) and CommonMark indentation-column machinery is untouched — that is what stops a refusal wrapped in a code fence from passing as real headings, and it survived four review rounds to get right.

## Also in this PR

- **iOS/Apple Mail dark mode fix retained** — the `color-scheme` meta tags and `:root { color-scheme: light dark; }` Apple requires. The media query was always correct; the document simply never opted in, which is why the real email rendered light against a dark Mail UI.
- **Removed** the now-dead source-chip renderer passes (briefing prose carries no source headings or inline tags).
