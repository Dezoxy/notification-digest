## Description
`send_digest` set only Subject/From/To. `Date` is required by RFC 5322 and a missing `Message-ID` is a routine spam-scoring signal. iCloud's submission server patches both in on the way out, so mail still flowed — but relying on a relay to repair your headers isn't a property worth depending on, and pre-stamped headers read as more legitimate to filters. Surfaced when digests started landing in spam after moving to a brand-new sending domain.

The Message-ID domain comes from the From address rather than `make_msgid`'s hostname default (a random Docker hex string in-container, unrelated to the sending domain). A From with no usable domain falls back to the default rather than raising — this is a header nicety and must never fail a send.

Also refreshes `.env.example` to the current addresses. 345 tests pass, ruff clean.
