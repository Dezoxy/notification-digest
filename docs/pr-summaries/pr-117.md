## Description
Follow-up to #116, which fixed the bubble's nested borders but **dropped the icon** from the design you picked.

## Why it wasn't in #116

The icon needs a wrapper around the input, and the input ships `[hidden]` until `client.js`'s filter IIFE reveals it — so a naive wrapper leaves a bare magnifier floating above the archive link wherever that reveal never happens.

That's **not only the no-JS case**: the IIFE also bails *before* the reveal on digest and arc pages, which carry the same masthead bubble but have no ledger to filter.

## The fix

Hide the **pair**, keyed off the input's own state:

```css
.searchpanel:has(.filter[hidden]) .searchfield { display: none; }
```

`:has()` rather than a client-script change — and it's **already used in this stylesheet** (`.settingsrow`, ~line 400), so it's established practice here, not a new dependency. The divider rule moves to the same mechanism, since the input and the link stopped being siblings once the wrapper landed.

The icon inherits `.searchfield`'s color via `currentColor`: `--faint` at rest, `--accent` under `:focus-within`. So the glyph and the panel border enter the focus state **together** — one indicator, which was the whole point of #116.

## Markup safety

The input keeps its class, its attributes, and its `[hidden]` default. Only its depth changed. All three JS lookups survive that, checked before writing the wrapper:

| lookup | why it's safe |
|---|---|
| `input.form` | a property, not a selector |
| `filter.closest("details.searchpop")` | ancestor query — `.searchfield` is inside |
| `pop.querySelector(".filter")` | descendant query |
