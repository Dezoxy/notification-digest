# PR #158: fix(pdf): stop tall diagrams leaving blank pages behind
[View PR](https://github.com/Dezoxy/notification-digest/pull/158) · @Dezoxy · merged 2026-09-20 · `25e00f0` · `fix/pdf-blank-pages -> main` · +9/-0 across 1 files

## Description
The architecture PDF carried pages holding nothing but the running header and
footer. Two here, one in architecture-base, one in hopin.

## Cause

Pandoc caps an image's **width** at the text block and never its **height**. The
builder sends a view to a landscape page only when it is wider than 1.3:1, so a
**tall** view stays in the portrait text flow at full width — and three of the
eight here render taller than the page can hold:

| View | Pixels | Height at 17cm wide |
|---|---|---|
| Security | 2604×4461 | **29.1cm** — an A4 sheet is 29.7cm |
| Landscape | 2380×3850 | **27.5cm** |
| DigestRun | 1932×2753 | **24.2cm** |
| *portrait text block* | | *~24cm* |

LaTeX cannot place a figure that does not fit where it falls, so it pushes it to
a page of its own and leaves the remainder of the previous page empty.

## Fix

Cap the height as well as the width, aspect ratio kept, so a tall view shrinks
to fit instead of overflowing. This is the standard pandoc recipe
(`\maxwidth`/`\maxheight` + `\setkeys{Gin}`), added to the same
`header-includes` block that already sets the landscape page geometry.

`0.92\textheight` rather than the full height, so a heading sitting above a
figure does not push it over the edge again.

**Raising `LANDSCAPE_RATIO` would not have worked** — a landscape page is
*shorter*, so a tall diagram fits it worse, not better.

## Verification

Measured by extracting per-page text and image objects, not by eye:

| | Before | After |
|---|---|---|
| Pages | 120 | **118** |
| Blank (header/footer only, excluding the cover) | **2** | **0** |
| Pages carrying a diagram | 15 | **15** |

Same 15 diagram pages, so nothing was dropped — the three tall views are scaled
down rather than pushed out.
