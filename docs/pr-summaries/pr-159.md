## What changes

Three hairline rules separate the end of a digest page into its parts, and the
model byline becomes one labelled line per leg:

```
…more than HUF 168 million.³²
───────────────────────────────────────────────  ① new
From 131 items; 23 informed this briefing, …      (muted)
───────────────────────────────────────────────  ② new
SOURCES  ■ news 54  ■ x 48  ■ telegram 14 …
WRITTEN BY       ↻ openai/gpt-5.6-sol · high
TRANSLATED WITH  ↻ openai/gpt-5.6-terra · high
───────────────────────────────────────────────  ③ already existed
← ALL DIGESTS
```

- **Labels** — EN `Written by` / `Translated with`; HU `Írta` (unchanged — it
  already meant "written by") / `Fordította` (**new, flagged for owner review**).
- **`✎` and `⇄` removed** — the label now names the leg.
- **`↻` kept, and now means exactly one thing**: an OpenRouter fallback model
  served that leg instead of Claude. On a normal day the line is just
  `Written by claude-opus-5 · high`.
- **In-chip `HU` marker removed** — "Translated with" says it.

## ① was a regression, not a missing feature

The app has always emitted the closing line as `<p class="foot">` with an inline
hairline border. The site strips inline styles so its own themed CSS applies
(the email's light-theme colours broke dark mode) and relies on the class
instead. But the site only ever styled **`.closing`** — the About page's caveat.
Nothing styled **`.foot`**, so once the stripping landed, the rule the design
intended silently vanished from every digest.

I confirmed it end to end rather than inferring it: pulled digest 548's
markdown from `state.db` (read-only), ran it through the app's real
`render_body_html`, and it produced `class="foot"` with the border — which the
site then stripped.

## The first fix passed every test and was still wrong

Adding `.foot` beside `.closing` passed **all 49 tests** and byte-matched
**every golden**. In a headless render, the closing line then painted
`rgb(236,237,240)` — the **brightest** text on the page — against body text at
`(195,201,212)`:

| Rule | Specificity | Effect |
|---|---|---|
| `.digest p` | (0,1,1) | sets colour and margin, beating a bare `.foot` (0,1,0) |
| `.digest p em` | (0,1,2) | deliberately brightens italics — and the closing line is entirely `<em>` |

Now `.digest p.foot`, plus `.digest p.foot em { color: inherit }`. Re-measured:
**`(154,161,175)`**, exactly the muted tone of the SOURCES label. Goldens prove
the markup string; only a render proves the paint.
