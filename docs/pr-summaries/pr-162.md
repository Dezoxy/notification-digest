## Description
feat: short model names on the digest page, and pin the translate model

Owner-requested. The byline read

  Written by       claude-opus-5 · high
  Translated with  sonnet · high

and now reads

  Written by       Opus 5 · high
  Translated with  Sonnet 5 · high

with fallbacks just as short (↻ GPT-5.6 Terra · high).

Site: modelDisplayName shortens the known id shapes -- claude-{opus,sonnet,
haiku}-N[-N] to "Opus 5" / "Sonnet 4.6", gpt-N.N[-suffix] to "GPT-5.6 Sol",
glm-N.N to "GLM-5.3", after stripping any provider prefix. Any id it does not
recognise is returned unchanged, so a new model never renders blank or
mangled. The exact id moves to a title="" tooltip rather than being lost.

App: TRANSLATE_MODEL now defaults to claude-sonnet-5 instead of the "sonnet"
alias. The alias was the real problem, not the formatting: the CLI resolves
it at call time and silently moves when a newer Sonnet ships, and that same
value is what provenance records. Labelling it "Sonnet 5" would have been true
until the day it quietly was not. Summarize is already deployed pinned to
claude-opus-5; translate now matches. Upgrading becomes a deliberate one-line
change. The default was duplicated -- the dataclass field AND from_env's own
fallback -- so both moved; the test caught the second one.

Existing rows: production has recorded "sonnet" 84 times, all between
2026-09-04 (when provenance began) and today, all in the Sonnet 5 era -- the
app's own translate_model_fallback comment contrasts that alias's Sonnet 5
with the older 4.6. So the bare alias maps to "Sonnet 5" for history only, with
that reasoning in a comment. No other alias is mapped: none was ever recorded,
and a guess would go stale.

Security: the tooltip puts the raw id inside an HTML attribute, where the risk
is a quote closing the attribute, not a tag. esc() escapes both quote kinds.
The drafted test only tried "<img src=x>", which cannot catch this, so there is
now a breakout test -- and a mutation run proves it bites: with quote-escaping
removed from esc(), exactly that test fails while the <img> test still passes.

docs-sync: README and .env.example documented the alias default; PLAN.md did
twice more and quoted raw ids in the byline example. PLAN.md also claimed
translation runs at a "fixed, cheaper medium effort" -- stale since the
TRANSLATE_EFFORT knob, whose default is high in config.py, from_env and
translate.py. That was pre-existing, but in the sentence being rewritten, so it
is corrected here. CONTEXT_MODEL still documents the "sonnet" alias, which is
still true: context primers are never displayed, so they are out of scope.

Verified: npm test 51/51 with all 9 goldens byte-matched and prettier clean;
ruff clean, pytest 1300 passed; make docs 11/11; rendered in headless Chrome.

Takes effect in production only once homelab's myapps_digest_translate_model
also moves to claude-sonnet-5 -- homelab sets the variable explicitly, so this
default alone changes nothing on the VM.
