## Description
Follow-up to #13 (merged while this was being built). Two small quality settings.

## `CLAUDE_EFFORT`, defaulting to `high`

The summarizer never passed `--effort` at all, so it ran at the CLI's default. That was an oversight, not a decision — I built `run_claude` before knowing the flag existed.

**Measured A/B on the real 50 items from delivered digest #3:**

| Effort | Wall clock | Words | Sections | Citations |
|---|---|---|---|---|
| default | ~20s | 1,052 | 7 | 33 |
| **high** | **81s** | 983 | 8 | 33 |
| max | 134s | 989 | 8 | 34 |

`high` vs default is a real improvement in editorial judgment — it correctly split conflated stories (Western intelligence support vs. strikes on Ukraine) into distinct sections and landed closer to the length target. `high` vs `max` is **not**: same eight sections, same story selection, within six words, for 65% more wall clock.

So `high` is the default, and it's **configurable rather than hardcoded** because the real cost isn't money — this authenticates via a Max subscription, so the currency is the owner's shared plan usage limits, spent by an unattended job running 8×/day forever. `max` would consume noticeably more of the same capacity he relies on for interactive work, in exchange for phrasing differences invisible in an inbox.

Validated against the CLI's own `--effort <low|medium|high|xhigh|max>` set, with `ConfigError` on anything else.

## Length now scales with the window

The prompt said *"roughly 900 words total, and never much beyond it **regardless of how many items came in**"* — that last clause explicitly forbade the scaling a busy window needs. Now: ~500–700 for a quiet window, ~900 typical, up to ~1,200 when the window genuinely holds many distinct significant stories, never padding to reach a number.

The 1,200 ceiling is deliberate rather than arbitrary: observed output overshoots a stated target by ~17% (1,052 against 900), so 1,200 lands near 1,400 in practice — about a 6-minute read, ×8 daily. Compression is the product; past that the reader is back to reading everything.

Stays prompt guidance with no code gate, consistent with the thin-validation approach.
