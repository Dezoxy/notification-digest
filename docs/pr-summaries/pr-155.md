## Why a drifted pin matters

The `Makefile`'s own comment on the pin states the rule:

> Keep it identical to the server's pin so the parser here is the parser there.

With the server on `2026.09.19` and this pin on `2026.06.28`, a local
`make check` was validating against a different parser than the one rendering
the workspace in the viewer. That silently voids the guarantee that makes a
green local check mean anything.

It was not hiding a defect today — the old pin reported the identical two
`IGNORE` lines — but the drift itself is the problem.
