# PR #148: docs: the X cookie runbook must set Key Vault tags, not just the value
[View PR](https://github.com/Dezoxy/notification-digest/pull/148) · @Dezoxy · merged 2026-09-06 · `21401c8` · `docs/x-cookie-runbook-tags -> main` · +71/-7 across 1 files

## Description
The runbook as written produced a rotation that deployed nothing. Fixing the two ways it misled.

## 1. `--tags` is mandatory

`az keyvault secret set` creates a new secret **version**, and versions do not inherit tags. So rotating dropped the `envvar` and `folder` tags the deploy discovers secrets by:

```
[?tags.folder=='digest'].{id:name, envvar:tags.envvar}
```
*(homelab repo, `.github/actions/azure-secrets`)*

The secret then falls out of the fetch entirely — `DIGEST_X_COOKIES` is never exported, the role's `when` guard on `myapps_digest_x_cookies_effective` fails, and `Write notification-digest X cookies file` reports **`skipping`**… while the deploy still reports success and the 38-day-old jar stays exactly where it is.

`file-encoding` survived only because `--file` re-adds it automatically, which is what made the loss non-obvious:

```
after rotation:  {"file-encoding": "utf-8"}
intact sibling:  {"envvar": "DIGEST_TG_SESSION", "folder": "digest", "file-encoding": "utf-8"}
```

Changes:
- The `set` command now passes all three tags (`--tags` replaces the whole set, so omitting one drops it)
- Verification checks the **tags** as well as the JSON shape — a jar with perfect keys and no tags is exactly the failure that looks fine
- Step 4 now says to check for `changed` (not `skipping`) on that task in the deploy summary artifact before believing it worked
- `set-attributes` documented for repairing an already-rotated secret without re-capturing cookies

## 2. Don't paste JSON at a zsh prompt

The heredoc form invited pasting the jar as a bare command, where `{...}` is brace expansion — zsh mangles it into a `command not found` that carries the credential straight into shell history.

Replaced with a `getpass` prompt that reads each value off `/dev/tty`, validates it (empty, whitespace, same-value-twice, whole-JSON-in-one-field) and writes the file `0600`. The secret never passes through the shell or argv.
