# PR #157: docs(architecture): make the PDF complete, and organised by audience
[View PR](https://github.com/Dezoxy/notification-digest/pull/157) · @Dezoxy · merged 2026-09-20 · `84cf5e8` · `docs/full-pdf-all-sections -> main` · +469/-430 across 36 files

## Description
The PDF is the deliverable — handed to people at different levels of a business.
It has to stand alone, and every reader has to find their section by its title.

It did neither.

## What was missing

Structurizr imports `overview/` and does not recurse, so the tab and the PDF
carried the narrative and the ADRs. Everything else existed only in git:

| | Files | Lines | In the PDF? |
|---|---|---|---|
| Narrative + ADRs | 13 | 1216 | ✅ |
| **Registers** — security, data, deployment, reliability, observability, risks, roadmap, requirements, principles, integration | **21** | **1383** | ❌ |

**More than half the architecture was absent from the artifact people are
handed.** A CEO does not click through to a private repository.

## How it is fixed

Each register is now symlinked into `overview/` as `NN-name.md`. It is still
authored **once**, in its own folder, where its IDs are owned — `ID_OWNERS` is
untouched and no file moved. Git stores all 21 as mode `120000`, so there is one
copy, not two. The numeric prefix fixes reading order.

I proved the mechanism before committing to it: Structurizr follows the
symlinks (**28** documentation sections) and so does the PDF builder
(**29** chapters, clean build, 7 of 8 views still embedded).

## Organised by audience

A section called "Assessing exposure" does not tell a CTO it is theirs. The
reading paths are now named for who reads them:

| | For |
|---|---|
| **Scope** | What is covered, and what was deliberately not built |
| **For stakeholders** | What it produces, what it costs, what could go wrong — no protocols, host names or code |
| **For the CTO** | Exposure, data, recovery, accepted risk, cost |
| **For engineers** | The design, the runtime, the decisions, the merge gate |
| **For operators** | How a change ships, what fails together, backup and recovery |
| **Glossary** | Terms with a specific meaning here |

"For stakeholders" is new. The other three are re-aimed from the task-based
paths they replace, and they now cite the registers as **sections of this same
document** rather than as links — the content is in front of the reader.

## Two checks that keep it true

- **`check_overview_complete`** — a register with no symlink is invisible in the
  PDF while still looking present in the repository. That is exactly the failure
  that is easy to miss, so it is now an error. Proven to fire by removing the
  disaster-recovery link and watching it fail.
- **`markdown_files()` skips symlinks** — an alias is not a second document.
  Counting it twice would demand its own index entry and report every finding in
  it twice.

## One structural fix the build exposed

The narrative sat at `##` while the registers are `#`, so the audience sections
rendered as subsections of nothing — backwards for a document navigated by
audience. Narrative headings promoted a level; every section is now a chapter.

## Caveat worth knowing

Symlinks check out as real links on Linux and macOS. A Windows checkout without
symlink support would materialise them as text files containing a path, and the
tab would show nonsense. Not a concern for this repo (the VM, CI and the
developer machine are all Linux/macOS), but it is the one environment
assumption this design makes.
