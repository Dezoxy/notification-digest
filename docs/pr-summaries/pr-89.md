## Description
## What

A fourth digest kind and seventh collector: polls one paid Patreon campaign via the site's own JSON API (cookie-authenticated, one HTTP request per run) and delivers each new post as its own Telegram message — Hungarian facts-complete summary, inline buttons for the post and its embedded video.

## Why the API and not RSS/email/browser

All four routes were tried live against the real account (2026-08-21):
- Native RSS is audio-only and creator-gated; this creator offers none
- Notification emails carry a truncated teaser, not the body
- Public API v2 is creator-oriented; a patron token cannot reach a campaign's posts
- Driving the logged-in Chromium works but costs a `claude -p` browser session per run, contends with jobs-refresh, and returned degraded data (13/22 timestamps missing, bodies empty, pinned posts out of order)

`session_id` alone authorizes the frontend API (verified against a no-cookie control), expires ~1 year out. ToS risk accepted by the owner, same stance as the X collector.

## Design points

- **Authorization is a field read, not an inference**: unauthenticated requests still return 200 with posts listed but `current_user_can_view: false` and empty bodies — a dead session would otherwise look like a quiet week. Pinned by a test.
- **One post → one digest** (`kind="patreon"`): the per-post message shape falls out of the existing delivery loop, inheriting the freshness guard and 429 breaker.
- **Telegram-only, hardcoded**: these summarize paywalled posts; the site channel is public. Suppressed flags are written unconditionally so a later `EMAIL_ENABLED` flip cannot mass-mail them.
- **First-run seeding**: newest 5 delivered, the rest absorbed into one all-channels-marked digest row.
- **Age cutoff (30d)** keeps the collector structurally clear of `prune_delivered_items` (90d) instead of cadence-dependently clear.
- **Facts-complete, analysis-light Hungarian prompt**: every public fact and number carried; the creator's reasoning indicated, not reconstructed. Long summaries split across a reply chain with status-preserving partial-send semantics.
