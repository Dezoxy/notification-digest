## Why it was rejected

1. **Duplication.** ECC is installed as a plugin; its agents, skills and
   commands are already reachable as `ecc:<name>`. A per-project copy is a
   second, divergent set that ECC updates never reach.
2. **Direct contradiction.** ECC's Python rules disagree with this repo's own
   Conventions on three counts:
   - `black` + `isort` vs. the ruff-only rule
   - `os.environ` + `dotenv` at call sites vs. "read exclusively in `config.py`"
   - `pytest --cov=src` vs. a package that is `digest/` (and no pytest-cov dep)
3. **Silent attribution flip.** It writes `{"includeCoAuthoredBy": false}`.
   No commit in this repo carries that trailer and the global setting is unset,
   so that is the owner's call to make explicitly — not a tooling side effect.
4. **The installer does not run here anyway** — it aborts with
   `Missing dependency 'sql.js'` because the plugin-marketplace install never
   ran `npm install` in the ECC checkout.

Verified non-destructive first: no planned path collided with an existing file,
so `CLAUDE.md`, `docs-sync` and `pr-summary` were never at risk.

## What was kept

- **`.claude/settings.json`** — a narrow allowlist for the real toolchain (uv,
  ruff, pytest, the worker's npm scripts, read-only git/gh), plus denies for
  `git push origin main`, force-push, `npm/uv publish`, and the secret files
  `.gitignore` already covers. This follows the skill's own rule 4, "keep
  permissions narrow".
- **The decision, written down** in `CLAUDE.md` + `AGENTS.md` under a new
  "Agent harness" section, so a later session does not re-run the install and
  land 800 files.
