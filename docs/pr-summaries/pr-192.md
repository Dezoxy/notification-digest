## Description
## What this does

Makes the path from a merged change to the Azure jobs automatic, while everything that is not a pure image bump stays on the existing manual plan/apply.

1. **Auto-release** (`auto-release.yml`, new). A merge to `main` that touches shipped files (`Dockerfile`, `digest/`, `prompts/`, `pyproject.toml`, `uv.lock`) runs `ruff` and `pytest`, tags the next patch version after the highest `vX.Y.Z` tag, creates the GitHub release and calls `release.yml` to build the image. Docs-only, workflow-only and infra-only merges release nothing. Minor and major bumps stay a manual tag.
2. **Tracked image pin** (`infra/azure/image.auto.tfvars.json`, new). The pin moves out of `AZURE_TERRAFORM_VARS_JSON`. Renovate bumps it (docker datasource) and automerges once CI passes.
3. **Guarded deploy** (`azure-deploy.yml`). A push to `main` that touches the pin plans as usual; the new `release-apply` job applies that saved plan only if `scripts/azure_release_guard.py` accepts it, the image exists in GHCR, and no job is running or due within five minutes.

## What the guard refuses

Anything except an in-place `update` of **every** `azurerm_container_app_job` whose only difference is the container image, identical across jobs, equal to the tracked pin, an exact tag or digest, with nothing unknown until apply (two provider-computed outputs are allowlisted). A create, delete, replace, a partial bump, an env/cron/secret change or any other resource fails the job and nothing is applied. An empty plan finishes without applying.

## Before or right after merging

- **Remove `image` from `AZURE_TERRAFORM_VARS_JSON`** (environment `azure-plan`). While it equals the pin the workflow ignores it with a warning; once Renovate bumps the pin, a stale value makes every plan fail closed.
- Merging this PR adds the pin file, so `azure-deploy` runs once. The expected result is an empty plan and a `noop` verdict.

## Trade-offs to be aware of

- **No human gate between merging shipped code and production.** The checks are lint, tests, CI on the pin PR and the guard. To stop a release: do not merge, or close the Renovate pin PR.
- **Schema migrations become automatic too** and are one-way; recovery is a restore from the daily backup, not an image rollback.
- **Renovate keeps one PR open at a time**, so the pin PR waits behind any other open Renovate PR.
- `release-apply` holds the `notification-digest-azure` concurrency group while it waits (up to about an hour).
