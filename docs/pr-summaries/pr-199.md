The repository became public on 2026-10-09. History and existing identifiers were deliberately **not** scrubbed (owner's decision). This PR adds what a public repo needs and closes the exposures that going public creates in the deploy pipeline.

## What this PR changes

- **Secret scan in CI** (`gitleaks.yml`, `.gitleaks.toml`): runs on every PR and push to `main`, not path-filtered. gitleaks 8.30.1 is pinned and its tarball checksum verified. The allowlist covers only rule `generic-api-key` in two test files (four known fixture findings), scoped by rule and path. Over the full history the scan reports nothing else, and it still flags a real-looking token.
- **Saved-plan artifacts** (`azure-deploy.yml`): a saved Terraform plan embeds the prior state, so on a public repo it is downloadable for the artifact's life. `release-apply` and the manual `apply` now delete the plan artifact in a final `always()` step (best effort, warns on failure), and `release-apply` and `apply` get `actions: write` for it. A manual `operation=plan` keeps its artifact until it is applied, or one day at most.
- **Docker build records** (`release.yml`): `DOCKER_BUILD_RECORD_UPLOAD: 'false'`. About 70 `.dockerbuild` artifacts already exist (90-day retention); delete them after this merges.
- **`SECURITY.md`** and an **"About this project"** README section (includes the X-terms note).
- **Docs**: "private repo" wording corrected in `CLAUDE.md`/`AGENTS.md` (identical), `PLAN.md`, `docs/azure-migration.md`; one new Hard-rules sentence says CI logs, PR bodies and fixtures are world-readable; new "Public repository" subsection in the runbook.

## What is exposed on a public repo, checked

- The three storage accounts have shared-key access disabled, so provider-computed storage keys inside a plan are unusable.
- The Log Analytics workspace shared key (ingestion only) can still appear in a plan. It cannot be disabled, because the Container Apps environment uses it. Someone holding it could forge log rows, for example a fake "job succeeded" line that hides a missing run from the freshness alert.
- Workflow logs, including Terraform output with resource IDs, are public. Old logs from before the switch are too.
- Nothing uses `pull_request_target`, and PR titles and bodies never reach a shell; only the PR number does. Both deploy environments are restricted to `main`. The container image is private (an anonymous pull gets no token).

## Not verified

- That the built-in token's `actions: write` can delete an artifact belonging to a different run (manual `apply`); the first manual apply will show it. If it fails, the step warns and the artifact expires in one day.
- Cleanup does not run if the runner crashes or the job times out, or if `plan` fails after uploading; the one-day retention is the backstop.
- The Log Analytics key claim is from the Terraform resource's documented behaviour; no real plan was inspected.
