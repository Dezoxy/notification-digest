## Config

Mirrors homelab's conventions so both repos behave identically: `config:recommended`, `prConcurrentLimit: 1`, `Europe/Budapest`, `after 6am before 7am`. `lockFileMaintenance` weekly for `uv.lock`.

**`twifork` is excluded on purpose.** Single-maintainer fork of the dead upstream `twikit`, still imports as `twikit`, handles a live X session cookie. Its pin comment in `pyproject.toml` requires a supply-chain re-audit of each diff — *no new network hosts, no new eval/exec/base64/subprocess/pickle* — before a bump can be trusted. A bot cannot assert that.

Same posture and same reasoning as homelab's `unifi_os_server_version`: **the update is real, the verification isn't machine-checkable.** The rule carries that reasoning in its own `description` rather than a bare `enabled: false` — the thing that makes the homelab config good is that its untracked pins say *why*.

**Two groups**, mirroring homelab: workflow actions (they move together against one file) and the news-site toolchain (prettier + wrangler share one verification run).

**One deliberate split:** a prettier **major** is pulled back out of that group. `workers/news-site` byte-compares rendered output against committed goldens, so a reformat is a review event, not a routine bump — its diff should be read on its own.
