# PR #73: docs: sweep stale 3-hourly references and stop advertising email delivery

## Description
Two follow-ups to the 6-hourly cutover (#72, homelab [#707](https://github.com/Dezoxy/toom-platform-homelab/pull/707)/[#708](https://github.com/Dezoxy/toom-platform-homelab/pull/708)). **No behavior change** — comments, docs and prompt text only.

## 1. Cadence sweep

41 live references still asserted a 3-hourly cadence **as current fact**, across module docstrings, `PLAN.md`, `CLAUDE.md`, `README.md`, and the three LLM prompts.

The prompt files matter beyond tidiness — `prompts/digest.md` literally told the model *"you write a personal briefing every 3 hours"*, which was simply false, and `prompts/daily.md` / `prompts/weekly.md` described their inputs as "3-hourly briefings".

**Four references are deliberately NOT swept:** the historical notes added in #72 that read *"this was 12h while the timer ran 3-hourly"*. Those describe the past on purpose. `docs/pr-summaries/` and `docs/incidents/` are likewise untouched — they are records of what was true when written, not descriptions of current behavior.

### Numbers were recomputed, not blind-replaced

| Where | Was | Now |
|---|---|---|
| `config.py` | 8x/day toolless window calls | **4x/day** |
| `main.py` | a day of coverage = 8 runs | **4 runs** |
| `summarize.py` | 8 runs × ~8 headings = ~64 lines | **4 × ~8 = ~32** |
| `publish.py` | false arc hits "×5 this week" within a day | **early on day two** |
| `PLAN.md` | `0/3:00:00`, `*/3h`, 50–100 items/window | `0/6:00:00`, `*/6h`, **100–200** |

`summarize.py` is the one where the *argument* changed, not just the number: ~32 now sits comfortably under the 50-line cap where ~64 pressed against it. The comment says so explicitly, and the cap **deliberately stays 50** — what it defends against (a pathological run, an unusually busy day) got no rarer with the cadence.

`PLAN.md`'s 50–100 items/window was a *measured* figure, so it's rescaled with its provenance kept rather than silently doubled.

`x.py`'s `~200`-notification cap is `_MAX_NOTIFICATION_PAGES * 40` — a per-run bound independent of cadence — so only the schedule name moved there.

## 2. Email is no longer the delivery channel

`CLAUDE.md`, `PLAN.md` and `README.md` all still *opened* by describing this as a service that "emails a digest". Since the multi-channel cutover (PR #25) the live channels on the real VM are the **Telegram TL;DR ping** and the **news site**; `myapps_digest_email_enabled` is `false` in the homelab host_vars.

**Email is not disabled in code, and the role default stays `true` on purpose** — the app refuses to start with every channel disabled, so a host that never configures site/telegram keeps working. The docs now state exactly that, instead of implying email is what ships.

The **GitHub repo description** was updated the same way:

> ~~Personal Telegram + X notification digest — scraped, Claude-summarized, emailed every 3h~~
> Personal Telegram + X notification digest — scraped, Claude-summarized, delivered to Telegram and a news site every 6h

That string becomes the image's `org.opencontainers.image.description` label at build time, so it was wrong on every published image — including `0.14.2`.
