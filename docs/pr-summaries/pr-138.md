## Description
Translation ran at a hardcoded `medium` effort (`_TRANSLATE_EFFORT` in `digest/translate.py`), on the reasoning that translation is mechanically easier than summarization — no editorial judgment, just a faithful rewrite of finished prose into Hungarian.

That reasoning is sound about the *shape* of the task, and is still why translation runs the cheaper `translate_model` tier. But the owner's call is that a faithful rewrite still benefits from the higher effort: Hungarian is the harder direction, and a mechanical task done badly is still done badly.

## Why a knob, not a flipped constant

1. **Release cost.** This app ships as a container image, so a hardcoded effort costs a full release train (tag → homelab bump → deploy) every time it's re-tuned. An env var is a homelab var change and a restart — and effort is exactly the kind of value you re-tune by feel after reading a few translated digests.
2. **Consistency.** `TRANSLATE_MODEL` and `TRANSLATE_MODEL_FALLBACK` were already independently configurable. The effort being the one hardcoded piece of the translation call was the odd one out.

## Design notes

- **Literal default, not a dynamic fallback to `claude_effort`** — unlike `verify_daily_effort`, which defaults to it. `translate_model` is already independent of `anthropic_model`, so coupling only the *effort* to the summarizer's setting would be a half-coupling, and a future `CLAUDE_EFFORT` change must not silently move translation with it.
- **Validated at config load** via the same `_optional_choice` + `_CLAUDE_EFFORT_CHOICES` path `CLAUDE_EFFORT` uses, so a typo fails at startup rather than at the model call.
- **`effort` threaded to both `run_claude` legs** (primary and the safeguards-refusal retry) *and* to `primary_effort`, so the provenance the site's "WRITTEN" byline renders reports the effort that actually ran.
- **The `medium` comment is rewritten, not deleted** — it explains why translation runs a cheaper model tier, which is still true and still load-bearing.

## Deploy coupling

Ships nothing on its own. Needs a tag → GHCR image → homelab pin bump. The homelab side adds `myapps_digest_translate_effort` / `TRANSLATE_EFFORT=` in the same release; the app tolerates the var being unset (defaults to `high`), so homelab-first is harmless, but bumping the image without the homelab change gives `high` with no way to tune it.
