## Description
## Why

The `azure-deploy` apply job fails closed unless `azure-production` has required reviewers. GitHub does not offer required reviewers on a private repository owned by a personal account: creating the rule returns `422 ... ensure the billing plan supports the required reviewers protection rule` (tested 2026-10-08). As merged, apply could never run.

## What changes

- `operation=plan` and `operation=apply` are now separate dispatches. Apply takes `plan_run_id`.
- Apply refuses to continue unless that run is a completed, successful `azure-deploy` `workflow_dispatch` run from `main` at the **same commit** being applied, then downloads that run's saved plan and applies exactly it.
- `plan_run_id` reaches the script through `env`, is validated as numeric before use, and cannot be the apply run itself.
- The plan summary prints the exact apply command. Artifacts still expire after one day, and Terraform still rejects a stale saved plan.
- Both environments are restricted to `main` by deployment branch policy (already configured in repository settings).

## What this does not do

It is not a second-person review. On a single-owner repository the previous gate would have been self-approval anyway; the approval is now the owner reading the plan and dispatching apply with its run ID.

## Docs

`docs/azure-migration.md`: the deployment-identity paragraph and the provisioning-stage paragraph now describe the two-step dispatch. `CLAUDE.md`/`AGENTS.md`, `README.md`, `PLAN.md` and ADR 7 were checked and left unchanged: "explicitly approved apply" and "reviewed plan/apply" remain true.
