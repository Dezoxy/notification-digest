# PR #104: feat(deliver): publish the digest without arc_contexts when the site 400s
[View PR](https://github.com/Dezoxy/notification-digest/pull/104) · @Dezoxy · merged 2026-08-27 · `4cbd700` · `fix/site-publish-degrade-on-400 -> main` · +274/-17 across 5 files

## Description
Follow-up to #103. That PR fixed the specific cap mismatch; this removes the **class of failure** it belonged to.

## The shape that hurt

The site's validator 400s the *whole* PUT over an **optional** field, and `_deliver_site` re-sends the identical payload every retry. So "retry next run" — the model every channel here depends on — degenerates into **fail-forever**.

Digest 249 sat unpublished for ~4h and would have stayed unpublished indefinitely, pending count growing 4/day, while every other line in the run logged green. The cap fix in #103 stopped this instance; nothing stopped the next one.

## Why `arc_contexts` is the field to drop

It's the only candidate, and for a specific reason: alone among the optional fields, it isn't scoped to the digest. `get_all_arc_contexts` is a full unscoped snapshot, so **its size tracks deployment age rather than this digest's content** — which is exactly why it, and not `topics`/`deltas`, is the field that grows into a cap. It's also decoration on a digest page rather than the digest itself. Publishing without it beats publishing nothing.

## Deliberately narrow

| decision | why |
|---|---|
| **400 only** | 401 = wrong key, 5xx = site down. Dropping a field can't help either — degrading there buys a second doomed request. A 400 with nothing in `arc_contexts` is about some *other* field, so there's nothing to degrade. |
| **One extra attempt, not a loop** | If the stripped payload is rejected too, the digest stays pending for the next run exactly as before. |
| **ERROR on a request that SUCCEEDED** | By severity alone this is a warning. But a silent degrade is precisely how the outage stayed invisible behind green runs, and the contract mismatch behind it heals no more on its own than the 400 did. Availability is bought here, but not with silence. |

Both calls share a `_put` closure so the degraded retry can't drift from the primary one — fifteen arguments must stay byte-identical, and two hand-maintained copies is how they'd stop being.
