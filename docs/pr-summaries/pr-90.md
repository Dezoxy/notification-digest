# PR #90: Positions tracker: ASI/Fetch in its own Telegram topic, on its own 4-hourly clock

## Description
Splits the owner's ASI/Fetch coverage out of the 6-hourly briefing into its own run mode, its own digest `kind`, and its own Telegram topic ("The Long Game", thread 354). Follows the Patreon precedent (#89) throughout.

## What changes for the reader

The window, daily and weekly briefs stop carrying position news entirely. It arrives instead as a project tracker every 4 hours — story, then a standing `**Where it stands:**` block so the position can be read without scrollback — and **only when something material happened**. A window of pure price chatter delivers nothing.

## Three routing axes

`state.positions_match_sql` is the single source of truth. `get_unsummarized_items` **negates** it and `get_unsummarized_positions_items` **asserts** it, so the two pools are exact complements *by construction*:

| Axis | Catches |
|---|---|
| `POSITIONS_TG_CHANNELS` | the dedicated Telegram channels |
| `POSITIONS_X_ACCOUNTS` | the project's X accounts (matched on `author`) |
| `POSITIONS_KEYWORDS` | the project's news in **any** other source — general crypto channels, news feeds, Reddit |

That property is load-bearing in both directions: an item matched by both is delivered twice into two topics; an item matched by neither sits unread until the 14-day prune deletes it. `tests/test_positions.py::TestPartition` asserts the union and the empty intersection directly, and that the in-memory predicate agrees with the SQL one.

## The keyword axis has an asymmetric error cost

A false positive does not merely misfile a story: the item leaves the briefing, and if the tracker then judges that window immaterial it is absorbed as a `positions-quiet` record — so an over-broad term makes unrelated stories **vanish from every channel, silently**. A false negative just leaves the story where it already was.

Precision is bought at the config layer: entries are length-floored at 4 characters with a `ConfigError`, not a warning, because the failure it prevents surfaces weeks later as an unexplained gap. `asi` is inside *basic*, *quasi*, *Asia*; `fet` is inside *feta*, *fetching*. Those four traps are pinned as tests.

## Also fixes

- **The positions backlog.** `summarize.py:249` recorded these channels arriving at ~77 items/6h against a **hard** 30-slot cap — a queue growing ~188/day whose only relief was the prune deleting the unread tail. With no competing lanes the cap is gone; its 30 slots return to the general lanes (news 55→64, telegram 50→58, x 50→58, reddit 35→40).
- **A LIKE-wildcard bug.** `_` is a LIKE wildcard and Telegram usernames contain one, so `t.me/asi_alliance/%` also matched `t.me/asixalliance/…`. The shared fragment now uses explicit `ESCAPE`.

## Its own message shape

The tracker is never published to the site — that would broadcast the owner's portfolio — so the window digest's TL;DR-plus-site-button shape would have shipped two sentences and a button to a page that was never created. `publish.send_telegram_tracker` sends the whole body into the topic with citations kept as inline URLs. The chunked reply-chain loop is extracted and shared with `send_telegram_post` rather than duplicated.

The 200–350 word budget is sized against the real render path: past ~360 words with its source links the message crosses `split_for_telegram`'s 3800-char threshold and becomes a numbered reply chain — two sends against an API this service has already been rate-limited by (`docs/incidents/2026-08-06-telegram-flood.md`). No code-level word cap, deliberately: `validate_output` stays structural-only per its own docstring.
