# PR #191: Accept Key Vault's explicit :443 in secret-copy pagination links

## Description
## Why

`scripts/migrate_azure_secrets.py` stopped on its first real run with `Migration stopped: Key Vault returned an unexpected pagination endpoint.` The source vault has more than one page of secrets, and Key Vault's `nextLink` carries an explicit default port:

```
https://kv-homelab-prod-th.vault.azure.net:443/secrets?api-version=7.4&$skiptoken=...
```

The check compared `netloc` to `VAULT.vault.azure.net` exactly, so the tool could never page through the real vault. Existing tests only used a `nextLink` without a port.

## What changes

- New `_is_vault_url()`: https only, hostname equal to the vault's own host, port absent or 443, no userinfo, malformed port rejected. Used for the pagination check and for the per-record `id` check (which now also requires https).
- Error messages are unchanged.

## Tests

- `:443` accepted for `nextLink` and for a record `id`.
- Rejected before any token use: port 8443, `http://`, both userinfo forms, a malformed port, and a `.attacker.example` suffix host.
