## What

`python -m digest daily` (a second homelab systemd timer fires it at 20:00 Europe/Budapest) synthesizes the last 24h of **window digests** — already-curated briefings, never raw items — into one 600–900-word evening brief with day-level arcs, stored as a `kind='daily'` row that inherits the entire delivery machinery (channel flags/retries, HU translation, site publish, flood guards, archive). Telegram lands in the dedicated Daily Brief topic (thread 90, `TELEGRAM_DAILY_THREAD_ID`). Display half: toom-edge #68 (deployed).

## Correctness constraints

- `get_recent_digests` filters `kind='window'` — daily headings must not pollute the window digests' `{{RECENT_COVERAGE}}` memory (explicitly tested).
- Thread selection by the digest's **stored** kind on fresh *and* retry paths — a failed 20:00 brief retried at 23:0x still lands in the daily topic.
- `summarize_daily` raises (the brief is the deliverable — the run must fail and alert), unlike the cosmetic soft-failing translation.
- Citations restricted to the union of the source briefings' stamped item URLs — same provenance pass as all model output.

## Backfill

`scripts/backfill_daily.py` (container-mounted, like the HU backfill): briefs for past 20:00 boundaries, framed at the historical evening (`summarize_daily` gained a keyword-only `now` override — review addition), backdated `created_at` (Worker orders by time now), `telegram_sent`/`email_sent` preset — **history never announces** — and publish failures heal via the normal pending pass. Idempotent (±6h existing-brief check).
