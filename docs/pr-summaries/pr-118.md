# PR #118: feat(news-site): open the masthead popovers on hover, desktop only
[View PR](https://github.com/Dezoxy/notification-digest/pull/118) · @Dezoxy · merged 2026-08-27 · `e055e7e` · `feat/news-site-hover-popovers -> main` · +980/-0 across 12 files

## Description
Hovering the SEARCH or SETTINGS chip opens its bubble; moving away closes it. Desktop only.

Both stay native `details`/`summary` — this only sets `.open`, so click, Enter, Escape, the `/` shortcut and the ⌘K palette keep working unchanged, and `[open]` stays the single source of truth every other handler reads.

## Three things in the existing code shaped the design

**1. The search bubble focuses its own input on open.** So a blanket *"don't close while focus is inside"* guard would pin a hover-opened search panel open **forever** — it focused itself on the way in. `keepOpen()` is a per-popover predicate instead: settings protects a reader who tabbed into the rows; search protects a **typed** query, not an empty focused field.

**2. Settings closes through an animated `close()` helper** with a `closing` guard. The pointer path routes through it rather than assigning `open = false`, so it animates like every other close path.

**3. An open panel deliberately swallows the next click anywhere on the page** — the dismiss handlers, plus the soft-nav bail reading `details.settings[open], details.searchpop[open]`. Hover-open makes "open" far more common and *accidental*, so a bubble left open after the pointer has gone would eat a link click.

That third point is why the close timer is **short (140ms)** rather than a generous grace period.

## The gap problem

Both bubbles sit `0.5em` below their chip, and that gap is outside both boxes — a pointer travelling chip-to-panel fires `mouseleave` halfway there. Rather than lengthening the close timer (see 3), the gap is bridged in CSS with a transparent `::before` on each panel, making the trip continuous.

## Touch

Gated on `matchMedia("(hover: hover) and (pointer: fine)")`. A touch device synthesises `mouseenter` on tap, which would open a panel that then has **no pointer to move away from it** — worse than the tap it replaced.

## Details

- Open delayed **120ms** so a pointer merely crossing the chip doesn't flash the panel; both timers cancellable by the opposite event.
- On close, focus inside the panel is blurred first — `details` hides its content, and leaving focus on a hidden element strands the keyboard there.

## Testing — a marker test, deliberately

The client script is inlined as **text** and never executed by the suite, so there is no DOM to dispatch `mouseenter` on. The test pins the parts whose loss would be silent: the pointer gate, both wirings, and settings closing via `close()`.
