## Description
You asked for twifork updates to be tracked. #106 excluded it outright; this reinstates tracking **without giving up the audit gate**.

## The exclusion had a cost I understated

It made twifork updates **invisible**, and invisible isn't safe. A fork going unmaintained — or shipping a fix `digest/collectors/x.py` actually needs — would never surface.

That's not hypothetical for this dependency specifically: the *reason* it's a fork is that upstream `twikit` (2.3.3, Feb 2025) went dead and broke X auth in March 2026. **Silence is exactly the signal that matters here**, and `enabled: false` guaranteed it.

## What changed

```json
"dependencyDashboardApproval": true,
"addLabels": ["supply-chain-audit"]
```

Renovate now detects and **reports** the update on the Dependency Dashboard, but opens no PR until you tick the box.

That keeps what the exclusion was protecting — each bump needs a hand audit of the diff against the previous pin (*no new network hosts, no new eval/exec/base64/subprocess/pickle*), which no bot can assert — while making the update visible. **Ticking the box is the decision to do the audit**, so the bump can't arrive looking like a routine one.

If you'd rather have it fully automatic, delete the rule — that's deliberately one edit away rather than the default.

## No urgency

PyPI has `2.3.3` / `2.3.4` / `2.3.5`; this repo is already on `2.3.5`. Nothing is pending. This matters when `2.3.6` appears.
