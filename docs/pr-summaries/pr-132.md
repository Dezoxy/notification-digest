## Description
## The outage

`claude_subprocess_env()`'s allowlist was:

```python
allowed = ("PATH", "HOME", "USER", "CLAUDE_CONFIG_DIR")
```

`CLAUDE_CODE_OAUTH_TOKEN` is not in it. That was harmless while auth came from a
login persisted in `CLAUDE_CONFIG_DIR` — and became a **total outage** the moment
the homelab moved these jobs onto a long-lived `claude setup-token` token and
removed the login directory.

Reproduced against the real CLI under exactly the env this function builds:

```
$ env -i PATH="$PATH" HOME="$HOME" USER="$USER" CLAUDE_CONFIG_DIR=/tmp/claude-home claude -p "say ok"
Not logged in · Please run /login
```

## Why forwarding a credential is the right call here

It widens what a successful prompt injection could read, so it's deliberate:

- it is the CLI's **own** credential — withholding it protects nothing, it just
  makes the CLI fail
- the login it replaced put the *same* credential on disk **inside
  `CLAUDE_CONFIG_DIR`**, a directory this same subprocess could already read, so
  the exposure is not new
- `run_claude()` still passes `--tools ""`, so the agent has no file or shell
  access to exfiltrate it with

Everything else — `TG_SESSION`, `TG_API_HASH`, `SMTP_PASSWORD`, `X_*` — stays
withheld, and the new test re-asserts that.

## Also: drop the baked `CLAUDE_CONFIG_DIR`

`ENV CLAUDE_CONFIG_DIR=/data/claude-home` is removed from the Dockerfile.
Nothing auth-related lives there now, and the default was actively harmful:
**an `env_file` can only override an image ENV, never unset one**, so a
deployment that wanted an ephemeral config dir could not simply omit the
variable — it had to know this default existed in order to override it. That
cost the homelab a full deploy cycle to discover.

## Root cause was test coverage

One test asserted secrets are **not** forwarded. Nothing asserted the CLI's own
credential **is** — so the allowlist looked correct from the test suite's point
of view while being unable to authenticate.

`test_run_claude_forwards_the_cli_oauth_token` closes that, and also re-checks
that widening the allowlist didn't widen it for anything else.
