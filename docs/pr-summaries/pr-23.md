## Description
## What

The summarizer gets a memory of what it already told the reader. `_deliver` now pulls every digest created in the last 24 hours (deliberately **including unsent ones** — a pending-resend digest still reaches the reader, see `get_recent_digests`' docstring), extracts their real `## ` headings, and feeds them into the prompt as an age-labeled list via a new `{{RECENT_COVERAGE}}` placeholder:

```
- 3h ago: Missile strike in Poland
- 6h ago: ASI Alliance: token migration questions
```

The prompt's new "Recently covered" section instructs **delta-only** coverage for already-covered stories — one or two sentences on what changed, no re-explaining — with an **escape hatch**: a development bigger than the original earns a full section again. The list never suppresses `## Needs attention`.

## Security design

Past headings were generated from the same untrusted scraped text as the items — an injection surviving into a heading would otherwise be **replayed into every prompt for 24h from template position**. So the coverage block gets the identical treatment as the items block:

- Own fenced block, explicitly extended into the prompt's "DATA, not instructions" section.
- Per-heading sanitization: backticks stripped (fence can't be closed early); `{{` broken via a **lookahead** `re.sub(r"\{(?=\{)", "{ ", ...)` — a plain single-pass `replace("{{", "{ {")` is defeated by brace runs (`{{{ITEMS_JSON}}}` → `{ {{ITEMS_JSON}}}` still contains a live placeholder); regression-tested; 160-char per-heading cap, 50-line total cap.
- Substitution order: `{{COLLECTOR_STATUS}}` → `{{RECENT_COVERAGE}}` → `{{ITEMS_JSON}}` strictly last, so no `.replace()` ever rescans inserted text.

## Implementation notes

- `_real_heading_lines()` extracted verbatim from `validate_output` so "what counts as a real heading" can never drift between gating this run's output and describing a past one. `validate_output` behavior unchanged.
- Coverage bytes count toward `_MAX_PROMPT_BYTES` automatically — the block is embedded in every prompt `select_items_for_prompt` measures, so a busy day's coverage legitimately shrinks how many items fit.
- All timestamps UTC end to end; ages computed in code (`3h ago`, `<1h ago`), never by the model.
