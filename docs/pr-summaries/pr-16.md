## What

A third item source: AI/robotics articles from owner-curated RSS/Atom feeds, flowing through the existing pipeline — same items table, same dedup, same summarizer, same briefing. The prompt clusters news with any Telegram/X discussion of the same story, so a lab release and the groups arguing about it become **one passage**, not two.

- **`digest/collectors/rss.py`** (new): synchronous urllib fetch (15s per-feed timeout, custom UA — some publishers 403 urllib's default) + feedparser parse. **No cursors**: a 12h lookback window + the `UNIQUE(source, source_id)` constraint is the idempotency layer — overlapping windows across runs are free, missed runs and late-published entries are tolerated, no state to corrupt.
- **Failure semantics deliberately diverge from telegram/x**: `failed=True` (⚠ banner, non-zero exit, Loki alert) only when *every* configured feed failed. One flaky publisher is routine and logged as a warning only.
- **`state.py`**: `source` CHECK widened to `('telegram','x','news')`. SQLite can't ALTER a CHECK, so deployed DBs get an idempotent table-rebuild migration (items + cursors): explicit column lists on both sides of the copy — legacy DBs have append-ordered columns from the old `ALTER TABLE ADD COLUMN` migrations, so named matching (never `SELECT *`) is what makes the copy exact. FK direction (`items` is the child of `digests`) makes the drop/rename safe with `foreign_keys=ON`.
- **`config.py`**: `NEWS_FEEDS` — comma-separated URLs, each validated `http(s)`; the collector is enabled iff non-empty (no separate flag to disagree with).
- **`main.py`**: wired after the X collector; `"news"` joins `failed_sources` — the banner builder is already generic over source names.
- **`prompts/digest.md`**: fourth material kind + a news-only interest filter (frontier models & labs, agentic & dev tooling, robotics & embodied AI, AI policy & business; marketing/listicles/stock notes/crypto promos are dropped to the closing count). The filter never applies to the reader's own groups/notifications.

## Provenance note

News entry links enter the email's anchor-provenance allowlist, so the collector's scheme+netloc validation on `entry.link` is load-bearing, not defensive fluff — a non-http(s) or hostless link never becomes an Item.
