## The model

Four containers across two trust zones: the one-shot Digest Runner and its
SQLite state on the private homelab VM, the news-site Worker and its D1
rendering copy on the Cloudflare edge. Seven collection sources, two model
providers, and the `tag → GHCR → pin → deploy` chain modelled but deliberately
kept out of the runtime views — none of it happens during a run.

Three layers only (Run, Data, Deliver) mapped onto the shared palette.
`model/styles-shared.dsl` is copied unchanged, as architecture-base requires.

## Views, and two defects the parser could not catch

Eight views, each answering one question, split at the `architecture-views`
budgets rather than enlarged. Seven collection sources would blow the 7/8
audience-overview budget, so **Context** answers the delivery question and
**Sources** the collection one.

Rendering and actually looking at them found two real defects:

1. **Containers** included both model providers. Their six long arrows
   dominated every automatic layout and crowded six labels into one band.
   Removed — that question belongs to `Context` and `DigestRun`.
2. **DigestRun** labelled steps 2 and 6 identically. Two relationships exist
   between the runner and Telegram — collection over MTProto, delivery over the
   Bot API — and without an explicit technology per step, the view drew the
   collection one twice. It was claiming the digest is delivered over the
   personal user session. Both steps now carry their own technology.

The register in `docs/architecture/README.md` records, per view, its question,
selection rule, registered omissions, update trigger and **visual verification
status**. Five views were reviewed at reading size; **Context, Sources and
Delivery were not**, and say so. `Landscape` sits at 12 elements against the
7/8 budget, kept there on the rendered evidence the budget rule requires.

**Findings the documentation work surfaced, not invented:**

- **TD-006** — a restore from backup can re-deliver an already-delivered
  digest. `digests` rows carry per-channel delivery flags and the pending
  retry pass re-sends anything unflagged, so restoring a snapshot taken before
  a digest was flagged makes it look pending again. That contradicts QA-01, the
  one absolute guarantee this system makes. Backups and the retry pass are each
  correct alone; nothing reconciles them. No automated safeguard today.
- **RISK-007** — the Reddit and Patreon collectors carry the same unofficial,
  ToS-risk posture as X, but `CLAUDE.md`'s hard rules name only X.
- **TD-005** — `config.py`'s in-repo defaults for `VERIFY_DAILY_ENABLED` and
  `CONTEXT_ENABLED` are off; production runs both on.

Honest gaps are recorded as gaps: no RTO is measured anywhere, the D1 rebuild
path has never been exercised, and `observability-architecture.md` states
plainly that a failed run is noticed by the digest not arriving.
