# PR #116: fix(news-site): one border for the search bubble, not three
[View PR](https://github.com/Dezoxy/notification-digest/pull/116) · @Dezoxy · merged 2026-08-27 · `63e4c42` · `fix/news-site-search-panel -> main` · +520/-140 across 10 files

## Description
Owner-reported: *"the search box is really bad looking."* The fault was **nested boxes**, not the bubble. A focused field drew three concentric rounded rectangles a couple of pixels apart:

```
.searchpanel   border 1px hairline, radius 14px, padding 1em 1.1em
  .filter      border 1px hairline, radius 8px
    :focus     outline 2px accent, outline-offset 2px   <- OUTSIDE the border
```

…and `min-width: 16em` against a field that didn't fill it left the input floating in dead space.

## The fix

| | before | after |
|---|---|---|
| panel | border, `radius 14px`, `padding 1em 1.1em`, `min-width 16em` | border only, `radius 12px`, `padding 0`, `overflow: hidden`, `min-width 19em` |
| input | own border + `radius 8px` | `border: 0`, full-bleed, own padding |
| focus | third ring outside the input border | `.searchpanel:focus-within` — the bubble itself |
| link | inline text under the field | full-bleed footer row, hairline above, hover fill |

The bubble owns the only border. `overflow: hidden` clips the children to its radius, so the input's corners never have to agree with the panel's. The link becoming a footer gives the bubble a reason to be a bubble — a field plus a way out of it — rather than a box with one control rattling around in it.

## CSS only — nothing scripted moves

`renderSearchBubble` is **not modified**. `.filter` and `.searchlink` keep their exact classes and DOM positions, which matters because the filter IIFE, the archive-search integration and the ⌘K palette's DOM scrape all bind to them via unscoped `querySelector`.

The divider is conditional — `.filter:not([hidden]) + .searchlink`. With no JS the input stays `[hidden]` and the link is the panel's only content, where a top border would read as a stray rule across an empty bubble.

## Dropped from the approved mockup: the magnifier icon

It needs a wrapper element around the input, and the input ships `[hidden]` until [client.js:867](workers/news-site/src/client.js) reveals it — so a wrapper would leave a lone icon floating for no-JS readers, fixable only with `:has()` or a client-script change. The nested-box fix is the substance; the icon can follow separately.
