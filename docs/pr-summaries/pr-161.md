## Description
## What changed and why

In the architecture viewer's **Documentation** tab, every document was
missing its title, both on the page and in the left-hand navigation. The
cause: the documents were titled with a single `#`, and Structurizr hides
that heading level. The PDF quietly re-levels headings, so it looked fine
and nobody noticed. The wrong convention came from architecture-base, which
is fixed upstream in Dezoxy/architecture-base#25.

This PR:

- **Retitles the documents** one level down (`#` → `##`, `##` → `###`, …).
  The first document keeps its `#` workspace title on purpose — that one is
  meant to be the cover line.
- **Adds a guard to the docs check**, so this cannot come back silently. It
  fails when an imported document's title would be hidden, when a document
  has no visible section heading, or when a heading skips a level. It ignores
  code blocks and decision records.
- **Updates the agent skills and instruction files** with the `##` rule.

No wording changed — only heading levels.

## How to verify by hand

1. Run the docs check (command below) — it should pass.
2. Change any document under `docs/architecture/overview/` to start with
   `# ` instead of `## `, run the check again — it should now fail, naming
   the file. Undo the change.
3. Open the viewer (command below), go to **Documentation**: every document
   should show its title on the page and as an entry in the left navigation.

Verified locally: the check passes, and in the viewer the number of
top-level navigation entries matched the document count exactly
(27 documents + the 6 sections of the opening overview = 33).

Commands: `make docs` and `make view`.
