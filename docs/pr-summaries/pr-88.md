# PR #88: feat(deliver): let a window run hide individual delivery channels

## Description
`python -m digest hide:telegram` / `hide:telegram,site` runs the ordinary window cycle but suppresses those reader-facing channels for the digest that run produces.

## Why

The 02:00 and 20:00 Budapest window runs ping the owner at hours nobody reads them. And the 20:00 one is *additionally* redundant on the site — the 20:30 daily brief republishes that same window 30 minutes later.

The two slots are **not** symmetric, which is why this is per-channel rather than a single "quiet mode":

| Slot | Hidden | Reasoning |
|---|---|---|
| 02:00 | `telegram` | No 2am ping, but the site still carries overnight news for morning readers — nothing else would until the 20:30 daily, 18h later |
| 20:00 | `telegram,site` | Genuinely redundant: the 20:30 daily republishes the same window to the site 30 min later |

Which runs pass which flag is a homelab scheduling decision, not this repo's.

## What is unaffected

Verified, not assumed:

| Consumer | Reads | Affected? |
|---|---|---|
| daily brief | `get_window_digests_since` — by `kind` | No |
| "recently covered" continuity | `get_recent_digests` — deliberately unfiltered by delivery | No |
| digest row / stamped items / archive | written identically | No |
| anything else gating on `site_published` | only the retry path | No |

## Marking the flag IS the mechanism

`get_pending_digests` treats any enabled channel with a `0` flag as an incomplete delivery. A merely-*skipped* channel would be picked up by the next run's `deliver_pending` and shown then — turning "hidden" into **"delivered late"**, which is worse than not hiding it at all. So the flag has to read resolved.

That means the stored flag says "done" for something never transmitted. The column is two-state and there's no `*_suppressed` field (adding one is a schema migration for a distinction only a log line cares about), so the `digest_delivery` line reports **`"hidden"`** rather than `"sent"` — the operational record stays honest even though the column can't.

## `hide:site` without `hide:telegram` is rejected at startup

Not a convention — a hard error. [`deliver_channels`](digest/deliver.py) only defers Telegram while the site publish is *not* done:

```python
if telegram_enabled and not telegram_done:
    if site_enabled and not site_done:
        ...skip...
```

A suppressed site reads as **done** there, so that combination would send a real ping linking to a page that was never published. A broken link shipped to readers is worth a startup error.

`deliver_pending` deliberately does not receive `hidden` — a digest pending there failed delivery on an earlier, non-hidden run and is owed its retry regardless of how this run was invoked.
