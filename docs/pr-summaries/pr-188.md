## Description
The Azure migration now stores Terraform state in a separately bootstrapped Azure Blob backend, gives the digest its own Key Vault, and prepares recovery and credential operations for cloud execution. Claude subscription OAuth remains configured. The owner-requested current CLI is pinned at 2.1.294, with official Node 22.23.3 copied from a digest-pinned Bookworm image; live authentication, quality and resource use must still pass the pilot. The previous exact-version Renovate hold is removed. The existing Azure subscription remains the default, with separate resource groups and scoped identities.

Provisioning has two stages: the foundation creates supporting resources with zero jobs; the operator then copies and verifies 17 runtime/registry secrets immediately before creating nine Manual jobs with schedules disabled. The new vault uses purge protection and seven-day soft deletion. Retention must be chosen before creation. The historical X-cookie seed and shared homelab alert credentials are excluded from the copy.

Credential operations preserve source secrets and default to refusing differing targets. An explicit `--apply --replace-target NAME` selects one reviewed rotation, creates a new target version and verifies readback without logging values. Legal secret names containing repeated hyphens no longer block metadata enumeration. The runbook includes scoped temporary grants and revocation, credential-edit freezes, final start verification, and post-cutover rotation against the dedicated vault. The cloud-cookie command validates a private JSON input and updates both canonical jars under the existing lease/watchdog without calling X or changing SQLite records. Reconciliation and state CLI commands also use private temporary workspaces, closing SQLite/stopping watchdogs/releasing leases before cleanup. Explicit export output remains durable for verification; configured persistent data is untouched.

Transient acquisition, reads and immutable bundle uploads receive bounded retries; upload retries use fresh names after possible acknowledgement loss. Renewal retries remain inside the original proven deadline, which extends only after an acknowledged renewal. Manifest commits and delivery are never blindly retried. Cursor jobs log successful skips for late starts or exhausted contention; daily, weekly and backup still require explicit catch-up. Missing/corrupt state and lost ownership remain hard failures. Unchanged content avoids another upload, while every checkpoint still builds/hashes locally and actual changes upload a full bundle.

Daily recovery copies use a separate account/resource group and writer identity attached only to the backup job. Each copy streams and verifies the stored bundle size/SHA-256 before publishing and verifying its compatible export manifest. A validated private export is reused across up to three transient copy attempts with 0.5/1-second backoff and a fresh prefix each time, including lost acknowledgements and interrupted readbacks. Retry waits/restarts must remain within the proven lease safety margin; corruption, authorization and ownership errors stop immediately. Abandoned prefixes expire through retention. Failed verification cannot complete the backup slot. Versioning, 14-day soft deletion and a scoped 30-day lifecycle are configured. This is separate-account recovery, not immutable retention or protection from subscription administrators/region-wide failure. Backend, runtime and backup locations must be distinct.

Pilot activation now requires authenticated Azure egress for every enabled collection/publication path, subscription/model/fallback checks and a restore from the separate account. Schema v8 requires preserving a consistent pre-upgrade source snapshot; 0.28.0 cannot reopen upgraded state. Recovery remains in Azure. No return-to-VM procedure is added.
