## Architecture Risks

One owner reviews and owns every row below — there is no separate risk board.
"Accepted" means a deliberate decision not to mitigate further, recorded here
rather than left implicit.

| ID | Risk | Likelihood | Impact | Mitigation or accepted decision | Related |
|---|---|---|---|---|---|
| RISK-001 | **SUPERSEDED 2026-10-08** by [RISK-008](architecture-risks.md) — the digest moved off the homelab, and the failure domain is now a single Azure region. As it stood while the VM ran production: the single Proxmox node hosting `01-myapps-vm` was the entire failure domain: the runner, `state.db`, and the primary backup snapshot job all lived on it | Low — home hardware, no internet-facing attack surface, but a genuine single point | High — losing the node loses the runner and the state database at the same moment | A daily local-plus-offsite snapshot exists and restore has been exercised once ([QA-05](../requirements/quality-attributes.md)); RTO for a full rebuild elsewhere is manual and has never been measured end to end. **ACCEPTED** beyond the existing backup — no second node was planned ([C-01](../requirements/constraints.md), [C-05](../requirements/constraints.md)). Closed on the move: the VM's old state directory and backups were left in place, frozen, and no longer back anything |
| RISK-002 | Collection credentials (`TG_SESSION`, X/Reddit/Patreon cookies) are the owner's own personal account sessions — a leak is an account-level takeover, not a service-credential rotation | Low — the jobs expose no listener, and the vault and state accounts answer only to Entra identities with a role assignment | High — the blast radius is whatever the personal account can do: read the owner's DMs and groups, post as the owner, and, for Patreon, spend against a paid subscription | Secrets reach the jobs only as Key Vault references resolved by the runner's managed identity (the X cookie jar lives in the runtime Blob state instead), never committed or logged ([C-06](../requirements/constraints.md)); none of these sessions carries MFA, as a property of using the accounts unofficially rather than a control this system chose to skip. **ACCEPTED** — there is no service-credential model available for a personal account |
| RISK-003 | The unofficial X client (`twifork`) breaks against an X change, or the account is flagged/locked | Medium — has already happened once: upstream `twikit` broke completely in March 2026 when X changed its webpack bundle | Medium — the X lane stops; nothing else in the pipeline is affected ([A-02](../requirements/assumptions.md)) | `X_ENABLED` isolates the collector; a failure is caught and banner-flagged rather than crashing the run; the dependency is pinned to an exact version, and every bump is gated behind Renovate's Dependency Dashboard with a mandatory supply-chain hand-audit ([ADR 1](../decisions/0001-pin-unofficial-x-client.md)). **ACCEPTED** for account suspension itself — no technical mitigation removes that risk |
| RISK-004 | Summarization cost is unbounded per run; no hard cap is enforced in code | Certain — this is the code's current state, not a hypothetical | Low today, because the primary path (the Claude CLI on the owner's Max subscription) is flat-fee; higher if the Claude API fallback chain triggers repeatedly, since that leg is billed per token against prepaid credits | Empty-item windows skip the model call entirely, enforced in code, not left to the prompt; `FALLBACK_TIMEOUT_SECONDS` bounds wall-clock, not spend; the federation's service account sits in a dedicated Claude Console workspace with a monthly spend limit ([ADR 9](../decisions/0009-fall-back-to-the-claude-api-over-workload-identity-federation.md)), which bounds the worst month outside the code, and the cost per fallback is unmeasured until the first real one logs a `claude api usage:` line. **ACCEPTED** — [QA-07](../requirements/quality-attributes.md) records this explicitly as an unmeasured, accepted exposure |
| RISK-005 | The summarizer refuses content under the model provider's acceptable-use policy | Observed in practice — `SafeguardsRefusalError` is a named, handled failure mode in `digest/summarize.py`, not a theoretical case | Medium — a window fails to summarize through the primary model | The Claude API fallback chain retries a different Claude model on a refusal (the diversity is across Claude models, no longer across vendors); `translate.py` carries its own fallback model for the same failure on the Hungarian pass; every digest records which model actually produced it ([ADR 2](../decisions/0002-summarizer-fallback-chain.md)). Residual: if every Claude model in the chain also refuses, the window still fails, with no escalation beyond the standard exit-code alert |
| RISK-006 | A third-party source removes free access | Observed in practice — Reddit's Data Team formally refused the owner's official API application (2026-08-06), which is why that collector now runs on a cookie session instead of OAuth | Medium — the affected collector's items stop appearing; every other collector and the run itself continue unaffected | Each collector is gated behind its own flag with isolated failure handling; RSS and Hacker News carry no auth dependency and are the lowest-exposure sources. **ACCEPTED** — [A-06](../requirements/assumptions.md) records that there is no budget line to replace a source that starts requiring paid access |
| RISK-007 | Reddit and Patreon carry the same unofficial-access, ToS-violation posture as X, but CLAUDE.md's hard rules name only the X collector explicitly | Confirmed in the collectors' own code: `digest/collectors/reddit.py`'s module docstring states it "mirrors the ToS-risk posture `digest/collectors/x.py` already takes... cookie session, unofficial API, ToS risk accepted by the owner"; `digest/collectors/patreon.py`'s docstring records "the same accepted-risk stance CLAUDE.md records for the X collector" | Medium for Reddit; for Patreon, the collector's own docstring notes the account is a **paid subscription**, so an adverse platform action costs more than X's free account does | Same collector-isolation and enable-flag pattern as X; the Patreon collector reads an explicit `current_user_can_view` field rather than inferring success from a 200 response. Not separately named as an accepted risk anywhere CLAUDE.md's hard rules are stated — **this is the gap this row exists to record**, not a resolved item |
| RISK-008 | One Azure region holds the jobs, the runtime state and the backup copy: a West Europe outage, or loss of the runtime storage account, stops the digest and can take the live state with it. Runtime storage is locally redundant (LRS) | Low — a regional loss is rare; no likelihood figure is recorded | High — no digest is produced until the region recovers or the state is restored elsewhere in Azure | The daily recovery copy sits in a separate storage account and resource group, written by a separate identity, with soft delete and a 30-day lifecycle ([ADR 8](../decisions/0008-isolate-digest-azure-state-and-secrets.md)); it is in the same region, with no immutability and no separate subscription. Recovery stays within Azure ([ADR 7](../decisions/0007-run-digest-as-azure-jobs.md)). **ACCEPTED** — no second region is declared ([C-01](../requirements/constraints.md), [C-05](../requirements/constraints.md)); replaces [RISK-001](architecture-risks.md) |
| RISK-009 | The Blob lease on the state manifest is the only guard against two runs overlapping. If it were lost or mis-proved, two runs could share the Telegram session or fork the state | Low — the lease is 60 s, renewed every 15 s, and a run that cannot prove it kills its process group; **real contention between two overlapping executions has not been tested** | High — a shared session risks the account, a forked bundle risks lost cursors or a duplicate delivery ([QA-01](../requirements/quality-attributes.md), [QA-06](../requirements/quality-attributes.md)) | Conditional manifest updates, a 35-minute cap on a run, fail-closed handling of a missing or corrupt bundle, and a bounded wait: cursor-based jobs skip a busy slot, while `daily`, `weekly` and `backup` fail and need an explicit catch-up run. **OPEN** — closes when contention has been exercised on the real stack. Replaces the VM's flock |
| RISK-010 | The recovery path is unproven: a restore from the backup account has not been exercised | Unknown — the daily copy is written and verified by readback, but nothing has been restored from it | High — a failure of the runtime state would be recovered for the first time under pressure, and [TD-006](technical-debt.md) would then apply | The restore procedure is written ([backup strategy](../reliability/backup-strategy.md)); a successful restore from the separate account is a pilot acceptance criterion. **OPEN** — closes with a recorded restore. The restore tested once on the VM does not carry over ([QA-05](../requirements/quality-attributes.md)) |
| RISK-011 | The Claude API fallback has not served a real digest: the chain (managed identity, Entra, Anthropic federation) was proven only by a one-off smoke test in the job environment on 2026-10-09 | Medium — it depends on three external token exchanges and a federation rule that can drift | Medium — if the primary `claude -p` call fails, the window is not summarized and the standard exit-code alert fires ([RISK-005](architecture-risks.md)) | The chain has no stored credential to expire ([ADR 9](../decisions/0009-fall-back-to-the-claude-api-over-workload-identity-federation.md)); `digest/openrouter.py` stays in the tree, unwired, until the first real fallback has worked. **OPEN** — closes when a real fallback logs a successful `claude api usage:` line |
| RISK-012 | The short-lived `azure-plan-*` workflow artifact in a public repository holds the nonsecret job settings in clear (its variables file and binary plan), some of them personal identifiers such as Telegram chat and thread ids | Low — the exposure lasts until the plan is applied (minutes for an image deploy, longer for a manual plan), up to one day at most | Medium — personal identifiers readable by anyone who downloads the artifact in that window; no secret value is in it, because secrets are Key Vault references | Plan logs mask the setting values, the artifact is deleted when its run ends or after one day at most, and both deploy environments are restricted to `main` ([Public repository](../../azure-migration.md#public-repository)). **OPEN** — closes by encrypting the artifact with an environment secret before upload |
| RISK-013 | Cloud spend is bounded by a budget alert, not a hard cap: the monthly budget notifies at 80% and 100% and does not stop anything | Medium — real storage and execution cost has not been measured | Low — a small workload, but the figure is unverified; the budget covers the app resource group only, so the backup and backend groups sit outside it | The pre-migration estimate and the reconciliation across all three resource groups are in the [migration runbook](../../azure-migration.md#alerts-cost-and-residency). **ACCEPTED** pending measurement; summarization spend is separate ([RISK-004](architecture-risks.md), [QA-07](../requirements/quality-attributes.md)) |
